# Расшифровка видео → интерактивная статья

Раздел **«Расшифровки»** (`/transcripts/`) — это разборы видео, превращённые в
интерактивные статьи: не пересказ, а инструмент, из которого читатель быстро
вытаскивает пользу и закрепляет её. Цель — максимум пользы и запоминания на единицу
времени.

## Как это работает

1. Пользователь присылает **ссылку на готовый анализ** (локальный файл или URL).
   Анализ готовят агенты соседнего проекта. Рядом может лежать **полная расшифровка**.
2. Твоя задача — собрать из этого **классную интерактивную статью** в стилистике сайта.
   Можно проводить доп. исследование (`WebSearch`/`WebFetch`), но главное — визуал и польза.
3. Каждая статья = **отдельная папка** `dev/src/content/transcripts/<slug>/`.

Сначала прочитай анализ (`Read` для файла, `WebFetch` для URL). Если данных не хватает
или их надо перепроверить — задействуй агента `video-analyst` (см. ниже).

## Анатомия статьи (что обязательно)

Соответствует Zod-схеме коллекции `transcripts` в `dev/src/content.config.ts`. Каждая
статья — это `index.md` с фронтматтером (структура) + телом markdown (необязательный
«Подробный разбор»). Поля:

| Поле | Что это | Обязательно |
|------|---------|-------------|
| `title` | Осмысленный заголовок — польза и ёмкость, **не** кликбейт из названия видео | да |
| `description` | Подзаголовок / meta-описание (1–2 предложения) | да |
| `tldr` | Ровно 2 коротких предложения — суть с ходу | да |
| `date` | Дата публикации `YYYY-MM-DD` | да |
| `cover` | Обложка: путь в `dev/public/...` или URL превью YouTube | желательно |
| `video` | `{ url, title, channel, duration, published?, platform }` — `published` (`YYYY-MM-DD`) это дата публикации видео из `meta.json`/«Дата публикации видео» анализа; показывается на карточке | да |
| `sourceAnalysis` | Ссылка на исходный анализ (для воспроизводимости) | нет |
| `ratings[]` | Оценки `1–5` по рубрикам `{ label, value, note? }` | да (≥1) |
| `tags[]` | Слаги из `dev/src/lib/tags.ts` | да (≥1) |
| `insights[]` | До 5 инсайтов `{ title, text }` — то, что меняет взгляд | желательно |
| `tips[]` | До 5 советов `{ title, text }` для саморазвития | желательно |
| `flowchart[]` | Логика повествования `{ title, detail?, type? }` | если уместно |
| `plan[]` | План внедрения `{ step, detail? }` | если есть рекомендации |
| `quiz[]` | 5 вопросов `{ question, options[], answer, correctText, wrongText }` | желательно |
| `related[]` | Слаги похожих расшифровок (иначе подберутся по тегам) | нет |
| `draft` | `true` — видно в `npm run dev`, но не в сборке | нет |

Подробные требования к каждому блоку — в файле
[references/article-spec.md](references/article-spec.md). Прочитай его перед сборкой.

### Рейтинги
Рубрики по умолчанию: **Актуальность информации** (на текущий момент),
**Содержательность** (плотность пользы, чем меньше воды — тем выше),
**Инновационность идей**. Добавляй свою рубрику (напр. «Доступность изложения»), если
это осмысленно. `value` может быть дробным (`4.8`). У каждой рубрики — короткий `note`.

### Блок-схема (`flowchart`)
Это **логика аргументации** видео, а не оглавление. Типы узлов раскрашиваются:
`premise` (предпосылка), `argument` (аргумент), `example` (пример), `conclusion` (вывод).
В `detail` — что именно происходит в этом шаге (раскрывается по клику).

### Тест (`quiz`)
5 вопросов на закрепление. `answer` — индекс правильного варианта (с 0).
`correctText` подтверждает и усиливает мысль; `wrongText` мягко поправляет и
подсказывает правильное направление. Оба обязательны для каждого вопроса.

## Теги: веди каталог

Каталог тегов — `dev/src/lib/tags.ts` (slug → подпись). **Сначала переиспользуй
существующие**, новый тег заводи, только если ни один не подходит, и добавляй его в этот
файл (иначе чип покажет сырой слаг). Это и есть «список уже использованных тегов».

## Оглавление статей

Отдельный файл вести не нужно — **живое оглавление** генерируется само на странице
`/transcripts/` (`dev/src/pages/transcripts/index.astro`): карточки с оценкой, тегами и
TLDR + фильтр по тегам. Главная и `/posts/` подхватывают расшифровки автоматически.

## Пошаговый процесс

1. **Прочитай анализ** (и расшифровку, если есть). При нехватке данных — `video-analyst`.
2. **Слаг**: латиницей, кратко, по сути видео (напр. `karpathy-llm`).
3. **Обложка**: если задана — положи в `dev/public/images/covers/<slug>.<ext>`; иначе для
   YouTube используй `https://i.ytimg.com/vi/<id>/maxresdefault.jpg`.
4. **Теги**: подбери из каталога, при необходимости дополни `dev/src/lib/tags.ts`.
5. **Создай** `dev/src/content/transcripts/<slug>/index.md` по схеме. Полную расшифровку
   (если прислали) положи рядом как `transcript.md` — она не публикуется.
6. **Связи**: проставь `related` или положись на авто-подбор по тегам.
7. **Собери и проверь**: `cd dev && npm run build`. Открой `/transcripts/<slug>/` в
   `npm run dev` и проверь, что блоки на месте, тест и план кликаются, иконки видны.
8. Если используешь **новую lucide-иконку** — добавь её в глоб
   `dev/src/components/ui/icon/icon.astro` (иначе она просто не отрендерится).

## Образец

Готовый пример со всеми блоками: `dev/src/content/transcripts/karpathy-llm/index.md`.
Это лучший шаблон — копируй его структуру.

## Чего не делать

- Не кликбейтить заголовок и не пересказывать видео дословно — выжимай пользу.
- Не лить воду в советы/инсайты: каждый пункт должен быть применим или менять взгляд.
- Не вставлять выдуманные факты/цифры — при сомнении проверяй или помечай.
- Не злоупотреблять нейро-градиентом (точечно: TLDR, рейтинги, кнопка play).
- Не редактировать вендореные компоненты в `dev/src/components/ui/` без нужды.
